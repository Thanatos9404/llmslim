# LLMSlim 1.0 roadmap

**Goal:** memory and context for AI agents with no LLM in the loop, deterministic, local and auditable, and stable
enough to depend on.

The three pillars:
- **Memory without extraction.** Keep what was said and select at read time. No model call to build memory, and no
  wrong extracted facts.
- **Cache-safe context for agent loops.** Keep the prompt prefix stable so provider prompt caches keep hitting. Never
  edit turns in a way a provider rejects. Stay under price cliffs. Report savings net of caching.
- **Trust boundaries.** Retrieved, remembered and tool text is data. It can never be promoted to instructions.

Status as of 29 October 2026, after 0.12.0. Releases: 0.10, 0.11 and 0.12 are out; 0.13 is the release candidate,
with the item H changes (including the Python 3.10 floor); then 1.0.0. Items are tracked as GitHub issues and pull
requests. Every quality change is chosen on development data and measured once on held-out test data, as in earlier
rounds.

LLMSlim Platform, the paid product built on Core, has its own plan. Everything listed here ships in the MIT Core.

## Known quality issues to fix before 1.0

These were found while building the memory API. Each will be validated on development data before it ships.

- **Stemming missed common word forms** ("move" and "moved", "time" and "times", "shop" and "shopping"). Fixed in #57 (0.10.0),
  which is neutral within noise on the dev splits and better on LoCoMo. Derived forms such as "allergy" and "allergic"
  are left to semantic relevance.
The two measurements below were taken before 0.12.0 changed how a long history is read; both are measured again
before 1.0.

- **The leftover budget might favour the oldest sessions** when little matches a question. Giving ties to the newest
  sessions instead measured neutral on the development splits: no LongMemEval question changed at 2,500 or 10,000
  tokens, and LoCoMo lost 0.4 points at 2,500. So nothing changes for now.
- **Dense retrieval over turns is still ahead on LongMemEval**: 80.6% to LLMSlim's 77.8% at 10,000 tokens. The gap is
  not significant on 180 questions, but it points the same way at both budgets. Optional hybrid recall is the
  candidate fix.

## What developers asked for (17 October 2026 research)

These are ranked by GitHub reactions and Hacker News points, and they set the order of the work above:
1. Long agent sessions lose work to context rot and compaction.
2. Prompt-cache breakage drives cost.
3. Long tool output fills the context.
4. Memory that writes wrong extracted facts.
5. Privacy and self-hosting.
6. Seeing what was in the context.

So:
- items B and E aim at coding agents first;
- MCP output compression is opt-in, because some MCP tools return live state, such as browser snapshots;
- every change keeps what the model has already seen byte-identical.

## Not in 1.0

- A generic compression gateway.
- The item F integrations (a LiteLLM guardrail, LiveKit Agents and Pipecat processors, a Cartesia Line example),
  which move to 1.x minor releases.
- More vendor integrations beyond those listed above.
- New learned-policy features.
