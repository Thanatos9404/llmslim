# LLMSlim 1.0 roadmap

**Goal:** memory and context for AI agents with no LLM in the loop, deterministic, local and auditable, and stable
enough to depend on.

The three pillars:
- **Memory without extraction.** Keep what was said and select at read time. No model call to build memory, and no
  wrong extracted facts.
- **Cache-safe context for agent loops.** Keep the prompt prefix stable so provider prompt caches keep hitting. Never
  edit turns in a way a provider rejects. Stay under price cliffs. Report savings net of caching.
- **Trust boundaries.** Retrieved, remembered and tool text is data. It can never be promoted to instructions.

Releases on the way: 0.10, 0.11 and 0.12 (release candidate), then 1.0.0. Items are tracked as GitHub issues and
pull requests. Every quality change is chosen on development data and measured once on held-out test data, as in
earlier rounds.

|---|---|---|

## Known quality issues to fix before 1.0

These were found while building the memory API. Each will be validated on development data before it ships.

- **Stemming missed common word forms** ("move" and "moved", "time" and "times", "shop" and "shopping"). Fixed in #57,
  which is neutral within noise on the dev splits and better on LoCoMo. Derived forms such as "allergy" and "allergic"
  are left to semantic relevance.
- **The leftover budget might favour the oldest sessions** when little matches a question. Giving ties to the newest
  sessions instead measured neutral on the development splits: no LongMemEval question changed at 2,500 or 10,000
  tokens, and LoCoMo lost 0.4 points at 2,500. So nothing changes for now.
- **Dense retrieval over turns is still ahead on LongMemEval**: 80.6% to LLMSlim's 77.8% at 10,000 tokens. The gap is
  not significant on 180 questions, but it points the same way at both budgets. Optional hybrid recall is the
  candidate fix.

## Not in 1.0

- A generic compression gateway.
- More vendor integrations beyond those listed above.
- New learned-policy features.
