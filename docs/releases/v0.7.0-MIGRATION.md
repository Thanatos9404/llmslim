# Adopting the v0.7 Agent Context Runtime

v0.6 users do not need to migrate. `compress()`,
`compress_chat_messages()`, `compress_documents()`, and `plan_context()`
continue to work with the v0.6 planner and signatures.

Use `ContextRuntime` when an agent application needs context preparation on
every model call. Create one runtime per application configuration. Call
`prepare_sync()` for purely local synchronous paths or `await prepare()` when
retrieving explicit sources. Check `prepared.feasible` before sending
`prepared.model_input` to a provider adapter. Inspect `prepared.quality` and
`prepared.trace` to understand reductions and infeasibility.

Session state is opt-in with `runtime.session(id)`. It is bounded and in-memory
by default; use external `ContextSource`/`ContextStore` implementations when
the host explicitly wants retrieval or persistence. No provider credential
belongs in an envelope, plan, or trace.

The v0.7 planner can be more conservative than v0.6: it preserves known
dependencies and rejects reductions below the quality floor. Expect an
explicit infeasible result where v0.6 might have fit by dropping a fact.
Measure task success on your workload before replacing a production plan.
