# Migrating to LLMSlim v0.6

Existing `compress()`, chat/RAG pipelines, rewrite providers, tool utilities,
MCP modes and CLI compression behavior remain supported. No migration is
required unless adopting planning.

The declared minimum Python version is now 3.9, matching the release CI matrix.
Python 3.8 environments must upgrade Python before installing v0.6.

Start by replacing a single global ratio with an explicit model budget:

```python
from llmslim import plan_context

plan = plan_context(
    messages=messages,
    documents=documents,
    query=query,
    model="sarvam-105b",
    max_input_tokens=16_000,
    reserve_output_tokens=1_024,
)
send_to_model(plan.final_context)
```

Check `plan.feasible` before dispatch. Set `raise_on_infeasible=True` if typed
exceptions fit your control flow. Do not assume `planned_tokens` is
provider-authoritative; it is an estimate unless a provider separately reports
usage.

External retrieval is now unified through `ContextSource`. Persistence is
explicit through `ContextStore`; planning never stores prompts automatically.
MCP SELECTIVE remains experimental and opt-in. Existing FULL and MEASURE_ONLY
flows should remain the default for production tool catalogs.

Hosted Sarvam is an application deployment feature, not an automatic library
behavior. Existing users make no paid calls. Operators who opt in must deploy
the dedicated server route with the key, durable quota store, HMAC secret,
explicit budgets, and `LLMSLIM_HOSTED_SARVAM_ENABLED=true`; see
`web/VERCEL_STUDIO_DEPLOYMENT.md`.
