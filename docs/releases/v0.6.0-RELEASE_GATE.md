## Hosted deployment safety state

The hosted route defaults off and requires all of the following before its
health response can report enabled: explicit enable flag, server-only Sarvam
key, MongoDB URI, and an HMAC identity secret of at least 32 characters. The
Vercel project is linked and authenticated but currently has no production
environment variables, so the deployed paid route cannot be enabled by
accident.

The route enforces body/item/output caps, network and session sliding windows,
per-identity token reservations, repeated-high-cost limits, expiring global
and per-client concurrency slots, atomic project daily/monthly spend
reservations, conservative settlement, sanitized errors, and aggregate-only
telemetry. BYOK is not exposed in the public Studio.

## External promotion prerequisites

Current public state was read before stopping:

- GitHub authentication is valid; tag/release `v0.6.0` does not exist.
- PyPI latest is `0.5.0`; `0.6.0` does not exist.
- TestPyPI latest is `0.1.0`; `0.6.0` does not exist.
- Vercel authentication and project linking are valid; production has no
  environment variables.

Required order after credentials are supplied:

1. Upload the two files from `.release-v06-release-dist` to TestPyPI.
2. Install `llmslim==0.6.0` from TestPyPI into fresh base and combined jobs and
   rerun import/smoke checks.
3. Provision MongoDB, add production `SARVAM_API_KEY`, `MONGODB_URI`, and a
   32+ character `LLMSLIM_RATE_LIMIT_HMAC_SECRET`; keep
   `LLMSLIM_HOSTED_SARVAM_ENABLED=false` for the first deployment.
4. Deploy, verify offline and disabled-hosted production behavior, then enable
   hosted mode and run one capped live smoke test only with explicit spend
   consent.
5. Push the reviewed commit, create/sign `v0.6.0`, create the GitHub release,
   and publish the exact artifacts to PyPI.
