# LLMSlim v0.7.1 engineering report

Status: **v0.7.1 release**, 30 September 2026. This report distinguishes local
structural results from provider measurements.

## Prior behavior and architecture (1–6)

1. **v0.7 behavior.** Every `RuntimeSession.prepare()` rebuilt model-visible
   context from retained messages, evidence, memory, tool results and schemas.
   It preserved raw context when it fit, or planned a quality-gated reduction
   under pressure. A ten-turn trace and mechanism distinctions are in
   [the cache design note](../runtime/CACHING.md).
2. **Transmission.** Generic, Sarvam and OpenAI-compatible adapters returned
   full prepared context on each stateless turn; the Sarvam host sent it.
   The OpenAI Agents bridge also returned the full text-only SDK input.
   Caller-managed trimming or compaction could reduce later requests.
3. **Existing provider behavior.** A provider or inference server may have
   automatically cached matching prompt prefixes even under v0.7. LLMSlim
   neither requested such controls nor measured their usage. Browser/HTTP
   caching and LLMSlim application/MCP caches are separate mechanisms.
4. **New architecture.** `CachePolicy` selects disabled, automatic observation,
   provider-memory or explicit mode. `CachePlan` records segments, stable
   prefix fingerprint, generation, invalidation, estimated reuse and bytes.
   `CacheManager` holds bounded tenant/session/model-scoped metadata in memory.
   `CacheTelemetry` holds separately parsed provider usage.
5. **Stable prefix.** Trusted system/developer instructions and authorized
   tool schemas lead. Conversation turns and tool results stay dynamic.
   Retrieved evidence is promoted only with explicit provenance and safe-order
   metadata; it remains evidence, never an instruction. Fingerprints cover
   provider, model, renderer, settings, policy, tool order and actual leading
   model input. Rewrites, tool/policy changes and expiry create invalidation
   reasons. Append-only turns can reuse more of a prior prefix.
6. **Planner economics.** With verified provider capabilities, matching stable
   metadata and caller-supplied rates, the progressive planner accounts for
   lost cache value when considering a rewrite. The 20k-versus-18.5k token
   regression test preserves the cheaper cached representation when a small
   compression would be more expensive. Hard budgets, quality gates and
   authorization still take precedence.

## Provider behavior (7–13)

7. **OpenAI.** An execution-free Responses builder supplies model-gated prompt
   cache controls, stable breakpoints where supported, a prefix key, and
   guarded `previous_response_id` continuation. It never calls an API.
8. **Anthropic.** A Messages builder places `cache_control` on the planned
   stable boundary in explicit mode or uses automatic control, with validated
   five-minute or one-hour TTL.
9. **Gemini.** The implicit path returns `generate_content` arguments. An
   explicit resource builder requires a sufficiently large stable prefix and
   caller-chosen TTL; the host owns resource creation and deletion.
10. **Sarvam.** Prompt-cache capability and usage reporting remain
    **unverified**. LLMSlim does not enable provider cache controls or estimate
    hits for this provider. No paid test was made.
11. **vLLM.** A chat builder passes a caller-owned tenant salt for a host
    already configured for automatic prefix caching. LLMSlim stores no server
    KV blocks.
12. **Hugging Face Transformers.** `TransformersKVSession` keeps a live
    DynamicCache or StaticCache in one trusted process. It validates model and
    tokenizer identity, revisions, config, renderer, tenant, device, token
    prefix, attention mask, positions, length and capacity, and clears state
    after a failed forward. It cannot be serialized.
13. **Conversation state.** OpenAI continuation is explicit opt-in. A recorded
    response ID is used only after a matching, append-only prefix with one new
    user turn. Instructions are resent. Prior tokens may still be billed.

## Measurement and safety (14–21)

14. **Telemetry.** Local prefix matches have status `estimated_reuse` (or an
    invalidation with partial stable-prefix reuse); only provider usage can
    yield `reported_hit` or `reported_miss`. Read, write, logical input,
    output, request bytes and optional host timings are separate fields.
15. **Cost.** Caller-supplied per-million-token rates price uncached, read and
    write subsets without counting any input token twice. If provider and
    local token totals disagree, combined savings are unknown.
16. **Privacy.** Cache metadata contains hashes, token counts, timestamps
    and optional opaque provider references, not prompt bodies, credentials or
    KV tensors. Tenant, session and model keys isolate entries. The Studio
    endpoint retains `no-store` and makes no provider call.
17. **Before/after.** The original frozen 112-case v0.7 baseline was rerun:
    67.9% budget success, 100% measured required-fact and tool retention,
    18.7% reduction and 118.23 ms mean local runtime planning latency. The
    new ten-scenario, 10/50/100-turn [offline benchmark](v0.7.1-BENCHMARK.md)
    compares six variants. All simulated turns were budget-feasible and kept
    the required canary. These are different corpora, so the percentages are
    not a paired quality or speed comparison.
18. **Cache hit rate.** Not measured. The 50-turn cache-aware run has 77,051
    **estimated** reusable read tokens out of 79,847 logical input tokens;
    this is a structural opportunity, not a provider hit rate.
19. **TTFT and latency.** Provider TTFT and full response latency were not
    measured. A separate ten-trial local CPU experiment with a random tiny
    Llama model measured 1.8032 ms median for full 129-token forward versus
    1.1589 ms for cached one-token continuation after prefill (35.7% lower).
    Last-token logits differed by at most 0.00000013. This validates local KV
    reuse, not provider TTFT or production-model speedup. Details are in the
    [benchmark](v0.7.1-BENCHMARK.md).
20. **Cost.** Billed cost before/after was not measured. The economic planner
    test verifies a decision under synthetic caller rates; it is not a
    provider invoice or live saving.
21. **Network bytes.** In the 50-turn stateless run, both v0.7 and cache-aware
    requests serialized to 173,990 bytes. The modeled OpenAI stateful path
    serialized to 86,875 bytes (50.1% less), assuming accepted response IDs.
    At 100 turns the figures were 542,890 versus 173,825 bytes (68.0% less).
    With a large tool catalog the stateful path grew from 96,060 to 104,306
    bytes, and with changing RAG from 21,040 to 22,110 bytes. Prompt caching
    alone does not reduce transmission.

## Verification and remaining limits (22–23)

22. **Tests and gates.** The package has offline tests for cache isolation,
    invalidation, provider payloads and usage, planner economics, Studio API,
    state continuation, and Transformers compatibility/fail-closed behavior.
    Full suite, coverage, Ruff, MyPy, wheel/sdist, clean install, Studio build,
    browser flow and secret scan results are recorded below after the final run.
23. **Known limits.** No live provider cache hit, TTFT, invoice, real-answer
    quality or server-side vLLM benchmark was run. Provider SDKs and model
    support change. The Gemini adapter is text-only and does not translate
    tools. The Transformers adapter relies on the host to update revision IDs
    after in-place weight changes. In-process cache metadata is not durable.
    The Studio deployment uses the hash-pinned v0.7.1 wheel from the release
    tag; core planning remains compatible with the previous wheel.

## Release gates

- Full offline pytest suite: passed; **90.28%** statement/branch coverage
  (required floor 90%). Three optional MCP tests skipped because `mcp` is
  absent in this environment.
- Ruff across the repository and MyPy across all 53 package modules: passed.
- Wheel and sdist: built; both installed in fresh temporary targets and
  imported as `llmslim 0.7.1` outside the repository source directory.
- Studio production build, TypeScript and ESLint: passed; ESLint reported
  23 existing warnings outside the changed Studio component. The browser Context
  Inspector completed a real local request through the Next rewrite and
  Python API, showing a feasible plan, quality gates, and Sarvam cache
  diagnostics without a provider call. The browser form disables unsupported
  provider-memory mode for unverified Sarvam and Generic capabilities.
- Secret-pattern scan of changed source, docs and tests found no credential
  signatures. `git diff --check` passed. Security regression tests cover
  tenant isolation, stale references, untrusted evidence, telemetry, and
  local KV compatibility failures. A tiny real-model `StaticCache` continuation
  also completed on CPU; the recorded local benchmark exercises `DynamicCache`.
- The Studio dependency points to the `v0.7.1` GitHub tag and the vendored
  wheel's SHA-256. No paid provider calls or PyPI publication were performed.
  GitHub publication and Vercel deployment are verified separately after the
  release commit is pushed.
